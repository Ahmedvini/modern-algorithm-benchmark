## 1. Untimed prepared-GPU correctness entry point

### Actual constraint

include/benchmark/cuda_timing.hpp:21–34 exposes constructor, info(), close() and sample() only. src/cuda/cub_timing.cu:78–118 always reads clocks/events in sample(), even for trivial inputs. Constructor/cleanup can be tested without sorting, but that is incomplete prepared-pipeline coverage. tests/test_cuda_sorting.cpp:19–38 supplies the existing full-vector std::sort oracle pattern for the different production adapter. Calling it again or duplicating raw-CUB calls in an unrelated test cannot establish the existing prepared framework's correctness.

**Both include/benchmark/cuda_timing.hpp and src/cuda/cub_timing.cu are frozen protected anchors.** scripts/cpu_gpu_protocol.py:76–88 currently allows only the approved CMake exception; scripts/cpu_gpu_provenance.py:44–95 independently enforces exact frozen source roots. Therefore a pure additive test-file change cannot provide full coverage under the unchanged v1 identity policy. This is the explicit decision needed before coding, not a reason to weaken provenance.

### Smallest complete proposal

Add one opt-in `tests/test_cuda_prepared_correctness.cpp` executable. Its required API is a proposed restricted test-access operation equivalent to `execute_prepared_untimed(session, const Values&, Values&)`, returning no latency fields. Prefer a test-access declaration/internal helper rather than exposing a new sorter or changing the production registry. Reuse the existing session's pinned buffers, key buffers, queried workspace and private nonblocking stream.

A small explicitly approved internal extraction is required so sample() and test access use the **same** transfer/SortKeys/output operations. An internal pipeline helper can accept timed versus no-op observation/synchronization policies. The untimed policy performs no clock reads, event recording or elapsed-time queries; it synchronizes the private stream before checking/copying output. The timed policy must preserve the exact existing start/stop positions, event sequence, synchronization, buffer reuse and allocation exclusions. Do not move host-input/output copies inside the existing timing boundaries. The constructor may still create its existing event objects; creation is setup, not elapsed measurement. No production cub_radix_sort, CUB pin, dataset generator or algorithm parameters change. Review this extraction as a protected framework change; it is not merely adding a test. No performance-equivalence claim can be made without separately authorized evidence.

The test generates frozen deterministic signed-int32 inputs and the CPU oracle outside execution. It transfers input, invokes CUB SortKeys(bits0–32) on the private stream, checks launch/API status, transfers output back, synchronizes and compares every element. Include empty/singleton, signed extrema, duplicate/ordered/reverse inputs, reproducible seeds, and small boundary lengths1/2/31/32/33/255/256/257/1023/1024/1025/65537. Repeated/interleaved correctness calls verify isolation; they have no warm-up or measurement meaning. Invalid sizes/alias/closed-session calls must reject before mutation. Use checked close()/RAII and preserve errors. Output only schema/scope, case/check/failure counts, failing input identity, GPU/CUDA/CUB/build/binary identities and status; no times, benchmark CSV, performance completion marker or study eligibility. A separate optional debug round-trip readback may isolate H2D failures; final oracle equality remains mandatory. Do not claim internal CUDA branches were covered merely from input shape.
