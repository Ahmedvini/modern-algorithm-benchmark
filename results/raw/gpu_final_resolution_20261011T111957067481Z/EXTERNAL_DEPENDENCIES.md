## Independent evidence authority

`scripts/cpu_gpu_evidence.py:19–27` has one fixed review location and an unset pin.
Neither environment variables, CLI options nor a retained user-authorization JSON
are supported trust-root configuration. The search found no matching actual
approval among8,612 JSON files,24 raw archives and the original cloud evidence
archive. The one similarly named cloud_evidence_review.json concerns historical
runtime discovery. It has neither the approval schema nor the current build context.

The real `approval()` path refused acceptance with “independent evidence/selection
review not installed.” It was inspected/called offline, without launching validation.
`docs/CPU_GPU_EVIDENCE_ENFORCEMENT_v1.md:22–38` explicitly identifies the circular
digest problem: a review that hashes a source file containing its own digest cannot
be installed by simply filling in that digest. A genuine independently protected,
non-circular authority and its review artifact are required. No such authority is
available here. Generating one locally and calling it independent would violate
the trust model and the user's no-fabrication/no-weakening constraints.

The accepted review must bind the exact session/source/build/binary/freeze context,
canonical source/build/Python paths, approved selection, CPU Release/sanitizer and
GPU build-provenance digests, all nine framework-record digests, five legacy
command references and preflight report. The current local v5 selection is expressly
not a study approval; candidate v4 remains inactive. `selection_manifest()` still
requires an approved v3/v4 identity with the exact current source map. No compatibility
change can honestly bridge an absent authority or missing current GPU evidence.
